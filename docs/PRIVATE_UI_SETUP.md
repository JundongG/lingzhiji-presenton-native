# Private UI test host

Use a host and account you control with a platform-supported private port forward.
Do not publish a forwarding port, disable authentication, or put secrets into Git.
The source add-on does not supply a hosting service or create a tunnel.

The upstream repository is https://github.com/presenton/presenton.git and the
reviewed commit is e158a014cc1e29da0a27fe539db08dcbcea5c69d. Apply this add-on before
starting the app. Use an external state directory, never the source repo itself.

## Dependencies

- Node.js >=20.9 for the web UI (tested here with Node 24.19)
- Python 3.11 for the pinned backend (3.12 is outside its declared range)
- uv for installing the frozen backend dependency lock
- No nginx or Docker daemon is needed for this two-process UI path
- No export-core bundle is needed for the new Native PPTX action
- The authenticated temporary HTTP download implementation requires POSIX no-follow file opens and file locking (tested on Linux); unsupported platforms fail closed for this delivery mode

In `presenton/servers/nextjs`:

```sh
CYPRESS_INSTALL_BINARY=0 NEXT_TELEMETRY_DISABLED=1 npm ci --ignore-scripts --no-audit --no-fund
```

In `presenton/servers/fastapi`, use an isolated environment outside the source tree:

```sh
UV_PROJECT_ENVIRONMENT=/path/to/private-runtime/venv uv sync --frozen --no-dev --no-install-project --no-build --python 3.11
```

If Python 3.11 is not installed, obtain it with uv's documented Python installation
flow in a user-owned directory first. Review and report any required build hooks or
system packages instead of silently installing them. Do not run upstream `start.js`
for this path: it expects system nginx and may install unrelated dependencies.

## Start the authenticated UI

```sh
python scripts/run_private_ui.py \
  --presenton /path/to/presenton \
  --state-dir /path/to/private-runtime \
  --python /path/to/private-runtime/venv/bin/python \
  --private-origin https://YOUR-VERIFIED-PRIVATE-FORWARD-HOST
```

Omit `--private-origin` for a genuinely local browser. The servers listen only on
127.0.0.1:3000 and 127.0.0.1:8000. Forward the UI port using the host platform's normal
PRIVATE setting; do not expose the API separately. Confirm the URL is HTTPS, belongs
to this instance, and requires the intended platform identity before proceeding.
This launcher starts the processes; it does not itself verify forwarding access.

The root page `/` contains the initial admin setup form. The user must create their
own local login and enter any model credentials themselves. Do not disable auth or
create credentials on their behalf. Custom provider settings are stored in runtime
SQLite and a mirrored configuration file; never copy that state into this repo.

For the first test, use one explicitly chosen model with structured-output and tool
support, and leave image generation disabled. The launcher disables optional Mem0,
community features and anonymous telemetry. It does not alter the existing export
buttons; legacy export paths can require additional upstream runtime components.
Use `Native PPTX (beta)` for the implemented path.

After credentials are entered, do not capture settings responses, database contents,
password/key fields or full logs. Verify with the requested synthetic generation and
focused edit results, then test native PPTX structure and output. Stop the launcher
with Ctrl-C when the private test is finished.

## What still needs a hosted test

A private forwarding origin can require host-specific development-origin or proxy
configuration. Verify the actual error and use the platform's documented method;
do not weaken browser security or create an ad-hoc public tunnel to make it work.
A local HTTP 200 does not prove user access. Full authenticated UI, real-model chat
and provider configuration must be tested on the chosen host before calling the
whole workflow complete.

## Native file delivery

The normal UI saves the current deck, requests an owner-scoped temporary export,
and shows an authenticated HTTP download link. The link requires the same signed-in
browser user, expires after 15 minutes, and is not a public share link. A periodic
cleanup removes only files generated by this feature; at most 10 active exports per
owner and 64 MiB per file are allowed. Download validation also rejects expired
files even before cleanup runs. Original presentation records are not deleted.

The new native namespace must route through its authentication/expiry handler, not
the ordinary static-file alias. The patch preserves other export paths and includes
nginx source rules plus FastAPI static-fallback checks. Real-host testing here uses
Next's private proxy, not nginx; nginx was reviewed and configuration-boundary tested
but its binary was not run in this environment. Review your complete deployment
configuration before production use.

The small Lingzhiji logo is the supplied original 200×200 image, not a newly generated
vector. UI language switches do not modify the model or its credential settings.
